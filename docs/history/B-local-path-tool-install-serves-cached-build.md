> **BLUF:** 로컬 경로 `uv tool install --force .`는 새 코드를 반영하지 않고
> exit 0을 내므로, 갱신엔 `--reinstall`을 쓴다.

## B (하지 말 것)

이 저장소를 자기 게이트로 검사하려면 CLI를 로컬 소스에서 다시 깔아야 한다.

그때 `uv tool install --force .`를 썼다.

`--force`가 이름 그대로 다시 만들 것이라 믿었고, exit 0을 성공으로 읽었다.

실제로는 낡은 빌드가 그대로 남았다.

버전 문자열이 `0.1.0`으로 고정이라 uv가 같은 것으로 보고 캐시를 재사용한다.

대조 실험 — 소스에 표식을 넣고 `--force`로만 다시 깔았다.

| 시도 | 소스 표식 | 설치본 반영 | 종료코드 |
|---|---|---|---|
| 1 | `MARKER-A` | 없음 | 0 |
| 2 | `MARKER-B` | 없음 | 0 |
| 3 | `MARKER-C` | 없음 | 0 |

세 번 모두 반영 0건인데 종료코드는 0이었다 — 실패 신호가 없다.

피해는 검사 자체가 사라진 것이었다.

낡은 CLI가 훅을 깔았고 그 훅엔 서식 검사가 없었다(79줄 대신 39줄).

동봉 규칙 조문도 3건 대신 2건이었다.

그 상태로 한 세션 내내 커밋했고 훅은 아무것도 막지 않았다.

같은 실험을 git URL로 돌리면 정상이다 — uv가 커밋 해시로 캐시를 가른다.

새 커밋을 만들고 `--force`로 다시 깔면 그 커밋이 반영된다.

즉 소비 저장소가 쓰는 경로는 멀쩡하고, 로컬 경로만 깨진다.

## G (대신 할 것)

로컬 소스에서 갱신할 때는 `--reinstall`을 쓴다.

`--no-cache`도 반영되지만 매번 새로 받아 느리다.

명령은 [AGENTS.md](../../AGENTS.md)의 검증 절이 정본이다.

깔았다고 믿기 전에 설치본을 직접 본다 — 종료코드는 이 실패를 못 알린다.

게이트를 새로 만들어 막지는 않는다.

문제는 낡은 훅이 깔린다는 것인데, 검사를 훅에 넣으면 그 검사도 같이 낡는다.

자기 자신을 검사 대상으로 삼는 구조라 그 방어는 필요한 순간에 부재한다.
