> **BLUF:** 로컬 경로 `uv tool install --force .`는 새 코드를 반영하지 않고 exit 0을 내므로, 갱신엔 `--reinstall`을 쓴다.

## B (하지 말 것)

도그푸딩용 CLI를 로컬 소스에서 `uv tool install --force .`로 다시 깔기.

- 문제: `--force`가 이름 그대로 다시 만들 것이라 믿고 exit 0을 성공으로 읽었다.
- 실제로는 낡은 빌드가 그대로 남는다.
- 버전 문자열이 `0.1.0`으로 고정이라 uv가 같은 것으로 보고 캐시를 재사용한다.
- 실측: 소스에 표식을 넣고 `--force`로만 다시 깔아 반영을 셌다.

| 시도 | 소스 표식 | 설치본 반영 | 종료코드 |
|---|---|---|---|
| 1 | `MARKER-A` | 없음 | 0 |
| 2 | `MARKER-B` | 없음 | 0 |
| 3 | `MARKER-C` | 없음 | 0 |

- 세 번 모두 반영 0건인데 종료코드는 0이다 — 실패 신호가 없다.
- 피해: 낡은 CLI가 깐 훅엔 서식 검사가 없었다(79줄 대신 39줄).
- 동봉 규칙 조문도 3건 대신 2건이었다.
- 그 상태로 한 세션 내내 커밋했고 훅은 아무것도 막지 않았다.
- 대조: 같은 실험을 git URL로 돌리면 정상이다 — uv가 커밋 해시로 캐시를 가른다.
- 근본 원인: 캐시 키가 버전이고, 그 버전이 소스와 무관하게 고정이다.
- 즉 소비 저장소가 쓰는 경로는 멀쩡하고 로컬 경로만 깨진다.

## G (대신 할 것)

로컬 소스에서 갱신할 때는 `--reinstall`을 쓴다.

- `--no-cache`도 반영되지만 매번 새로 받아 느리다.
- 명령은 [AGENTS.md](../../AGENTS.md)의 검증 절이 정본이다.
- 다만 명령을 고쳐 적는 데서 멈추지 않는다 — 언어 지시는 기억에 의존한다.
- 설치본의 배포 산출물이 소스와 바이트 동일한지 테스트가 대조한다
  (`tests/test_installed_bundle_matches_source.py`).
- 대조를 훅에 넣으면 자기참조다 — 훅은 설치본에서 나오니 낡은 설치본엔 없다.
- 테스트는 `uv run pytest`가 소스에서 돌려 언제나 현재 코드다.
- 그래서 자기참조는 훅에 박는 검사에만 해당한다.
- 게이트 신설 전체의 기각 근거로 넓히면 과잉 일반화다.

## 기각한 대안 — 버전을 커밋에서 파생

캐시 키가 버전이니 버전을 커밋마다 바꾸면 된다는 방향을 재봤다.

- 실측: `hatch-vcs`를 붙인 시제품으로 미커밋 편집 2회의 버전을 비교했다.

| 시도 | 상태 | 만들어진 버전 |
|---|---|---|
| 편집 A | 미커밋 | `0.1.1.dev0+g2737f599.d20260730` |
| 편집 B | 미커밋 | `0.1.1.dev0+g2737f599.d20260730` |

- 같은 커밋에서 편집하면 버전이 안 갈린다 — 사고가 난 자리가 정확히 거기다.
- 커밋 사이만 갈리므로 개발 중 되돌이엔 무효다.
- 기각 사유: 원인 하나만 덮으므로 산출물 대조 쪽이 더 넓게 막는다.
