> **BLUF:** `Refs`는 종료 키워드가 아니라 완결된 이슈가 안 닫혔다 — 완결이면 `Closes`를 쓴다.

## B (하지 말 것)

완결시킨 이슈를 PR 본문에 `Refs #N`으로만 적기.

- 문제: GitHub은 `close`·`fix`·`resolve` 계열만 머지 시 이슈를 닫는다.
- `Refs`는 링크만 만들고 종료 신호가 아니다(맨 `#12`와 기능이 같다).
- 실측: PR #7이 `Refs #3, #4`로 머지됐고 두 이슈는 엿새 뒤 손으로 닫혔다.
- squash 머지 탓이 아니다 — PR #9는 `Closes #5`로 정상 자동 종료됐다.
- 근본 원인: 완결 여부를 판단하는 순간이 없었다.
- 템플릿의 `Closes` 힌트는 최초 커밋부터 있었으나 저자가 그냥 지나쳤다.
- 그래서 안내 문구를 늘리는 처방은 같은 실패를 되풀이한다.

## G (대신 할 것)

이슈를 만들 때 상위 이슈의 sub-issue로 붙일지 먼저 정한다.

- sub-issue를 가진 이슈가 umbrella라 분류가 관계 데이터로 남는다.
- PR에서는 완결이면 `Closes`, 부분이거나 umbrella면 `Refs`를 쓴다.
- 모호하면 사람에게 물어 확정한다 — 완결 판정은 룰이 못 하는 의미 판단이다.
